# لوما · النظام المحاسبي

دورة محاسبية مزدوجة القيد داخل لوما:

```
عملية (بيع · شراء · مصروف · راتب)
  → Accounting Event   (luma-acc-events.js)
  → Journal Entry      (luma-acc-journal.js)
  → General Ledger     (Ledger)
  → Trial Balance      (Ledger.trialBalance)
  → Financial Statements (luma-acc-reports.js)
```

## الملفات

| الملف | المسؤولية |
|---|---|
| `luma-acc-core.js` | النقود (هللات صحيحة) · واجهة التخزين `AccRepo` · سجل التدقيق · دليل الحسابات |
| `luma-acc-journal.js` | محرك القيود (توازن، ترحيل، عكس) · الفترات المالية · دفتر الأستاذ والأستاذ المساعد · ميزان المراجعة |
| `luma-acc-events.js` | طبقة الربط (دور → حساب) · طبقة الضريبة · قواعد الترحيل لكل نوع عملية |
| `luma-acc-reports.js` | قائمة الدخل · المركز المالي · التدفقات النقدية · أعمار الذمم · الإقرار الضريبي · الإقفال · فحص السلامة |
| `luma-acc-ops.js` | الجهات · الصناديق والبنوك · الأرصدة الافتتاحية · التحويلات · التسوية البنكية · الأصول والإهلاك · القيود الدورية |
| `luma-acc-perm.js` | الصلاحيات المحاسبية — مفروضة عند حدود النطاق |
| `luma-acc-bridge.js` | ربط عمليات لوما القائمة بالمحرك |
| `luma-acc-ui.js` · `luma-acc-ui2.js` | شاشة «المحاسبة» بخمسة عشر تبويباً |
| `migrations/0001_accounting_core.sql` | مخطط PostgreSQL بنفس القواعد كـ CHECK و TRIGGER |

## القواعد المفروضة

1. **لا يُرحَّل قيد غير متوازن** — مجموع المدين = مجموع الدائن، بالهللة.
2. **القيد المرحَّل لا يُعدَّل ولا يُحذف** — العكس فقط، والأصل يبقى في الدفتر.
3. **لا ترحيل على حساب أب أو موقوف.**
4. **لا ترحيل في فترة مقفلة**؛ وإعادة الفتح تتطلب سبباً موثّقاً.
5. **السطر إما مدين أو دائن**، موجب، لا الاثنان ولا صفر.
6. **العملية الواحدة قيد واحد** — `source + sourceId` يمنع الازدواج.
7. **كل رقم في القوائم مشتق من الدفتر** — لا مصدر ثانٍ.

## لماذا الهللات؟

`0.1 + 0.2 !== 0.3` في العوائم. كل المبالغ داخل المحرك أعداد صحيحة بالهللات،
والتحويل عند الحدود فقط (`Money.from` / `Money.to`). هذا وحده يمنع اختلال
ميزان المراجعة بفروق التقريب.

## طبقة الربط — لا حسابات مكتوبة يدوياً

لا يُكتب رقم حساب داخل أي عملية. العمليات تطلب أدواراً (`cash`, `ar`,
`rev_service`, `vat_output`…) و`Mapping` يترجمها. تغيير الدليل = تعديل الربط.

## الضريبة

معزولة في `LumaAcc.VAT` (النسبة، التفعيل، التفكيك). تقرير الإقرار داخلي
للمراجعة. **الفوترة الإلكترونية المعتمدة (ZATCA) تتطلب توقيعاً وتجزئة متسلسلة
وإرساﻻً من خادم** — غير ممكنة من المتصفح، ولم تُدَّعَ هنا.

## حدود النسخة الحالية

التخزين `localStorage`: بيانات كل متصفح على حدة، وقابلة للتعديل من أدوات
المطوّر. لذلك:

- **سجل التدقيق ومنع حذف المرحَّل غير قابلين للفرض فعلياً** في المتصفح — هما
  مفروضان في طبقة النطاق، وحقيقةً في `migrations/0001` عبر TRIGGER.
- `AccRepo.tx` **تحاكي** الذرّية (لقطة واسترجاع)، وليست transaction حقيقية.

طبقة النطاق لا تعرف مصدر بياناتها: نقلها للخادم = كتابة محوّل `AccRepo`
يتحدث مع Postgres، دون المساس بقواعد المحاسبة.

## الصلاحيات

`luma-acc-perm.js` يلفّ الدوال الحساسة (إنشاء، ترحيل، عكس، إقفال، إعادة فتح،
دليل الحسابات، الربط، الضريبة، الأصول، التسوية، الافتتاحية) ببوابة
`Perm.require`. أربعة أدوار جاهزة: المالكة · المحاسِبة · مُدخِلة قيود · مراجعة.
المحاسِبة تُرحّل ولا تُعيد فتح فترة مقفلة؛ مُدخِلة القيود تُنشئ ولا تُرحّل.

**حدّ صريح:** الفرض الحقيقي مستحيل في المتصفح — من يملك أدوات المطوّر يملك
كل شيء. هذه الطبقة تمنع الخطأ لا الخصم؛ النظير الحقيقي سياسات RLS على الخادم.
كل محاولة مرفوضة تُسجَّل في سجل التدقيق بالدور والوقت.

## ملاحظة على دليل الحسابات

الصندوق (`1101`) والبنك (`1102`) مجموعتان منذ البذرة، ولكل منهما حساب افتراضي
(`110101` و`110201`). لو كانا ورقتين لتعذّر فتح صندوق لفرع جديد بعد أول ترحيل
عليهما — وهذا ما يمنعه المحرك صراحةً بحماية «حساب عليه حركة لا يصير أباً».
